## 2. 输入契约：商品清单.xlsx

### 2.1 参与上架的列

| 索引 | 列名 | 必填 | 取值/格式 | 校验规则 | 失败后果 |
|---|---|---|---|---|---|
| 0 | 商品ID | 是 | `P001`… | 唯一、非空 | precheck 失败 |
| 3 | 分类路径 | 是 | `瑜伽垫/安踏/轻微使用痕迹/189/TPE` | 五段：分类/品牌/成色/长度/材质 | 该行「上架失败」 |
| 6 | 价格 | 是 | 数字，元 | >0 | 该行「上架失败」 |
| 7 | 原价 | 否 | 数字，元 | ≥价格 | 该行「上架失败」或留空 |
| 8 | 发货设置 | 是 | `包邮` / `按距离计费` / `一口价` / `无需邮寄`，可加「支持自提」 | 枚举匹配 | 该行「上架失败」 |
| 11 | 套图目录 | 是 | `products/<ID>/套图/` | 目录存在且含图片 | 该行「上架失败」 |
| 12 | 描述 | 是 | 文本 ≤1500 字 | 非空 | 该行「上架失败」 |
| 13 | 状态 | 是 | 人工置 `待上架` 才入队 | 见 §3 | 不跑该行 |
| 14 | 失败原因 | — | 系统/人工写 | 只追加，不覆盖 | — |

> 其余列不参与上架，保留原样，不要删列（画布按索引读取）。

### 2.2 上游合同（只有两条）

| # | 合同 | 不满足时 |
|---|---|---|
| 1 | `products/<商品ID>/套图/` 内放待上传图片，按文件名升序，目录内不放非图片 | precheck 拦截整批 |
| 2 | 上述六列（3/6/7/8/11/12）填好 | precheck 拦截整批 |

## 3. 输出契约：状态与回执

### 3.1 状态值（写回 Excel 第 13 列）

| 状态 | 谁写 | 含义 | 人工动作 |
|---|---|---|---|
| `待上架` | 人工 | 允许入队 | 无 |
| `上架中` | 系统（点发布前） | 已开始处理，可能已点发布 | 崩溃后先对账，不直接改回待上架 |
| `上架成功` | 系统 | 发布后跳到 `/item?id=…` | 无 |
| `上架失败` | 系统 | 点发布**之前**的步骤失败 | 看第 14 列原因，修复后人工置回待上架 |
| `上架情况不明，待人工确认` | 系统 | 已点发布，但无法确认结果 | 人工到闲鱼后台核对，避免重复上架 |
| `中断·登录失效` | 系统 | 循环中登录态失效 | 重新登录后续跑 |

> 铁律：**点过发布之后不写「上架失败」**。无法确认一律「不明」。

### 3.2 回执表字段（验收用）

| 字段 | 来源 | 说明 |
|---|---|---|
| 商品ID | Excel 第 0 列 | 对齐用 |
| 最终状态 | Excel 第 13 列 | 六种状态之一 |
| 失败原因 | Excel 第 14 列 | 失败/不明时必填 |
| 平台商品ID | ledger / 成功页 URL | 成功行才有 |
| 处理时间 | 日志 | 开始/结束 |
| 重试次数 | 日志 | 本行跑了几次 |

> 回执可以是 Excel 的「状态+原因」两列，也可以是单独导出的汇总表；二选一，交付前定死。

## 4. 运行手册目录

| 章节 | 内容 | 验收要点 |
|---|---|---|
| 1. 前置条件 | Edge、固定 profile（端口 9224）、凭据文件、套图目录、商品清单 | 缺一项就跑不起来，手册要写清检查方法 |
| 2. 首次登录 | 启动浏览器 → 扫码 → 确认登录态 | 截图 + 失败提示 |
| 3. 批量上架 | precheck → 影刀 main → 等待结束 | 一次跑完，不需要中途手动点 |
| 4. 中断恢复 | 登录失效 / 残留「上架中」→ 对账 → 续跑 | 不重复上架 |
| 5. 失败处理 | 按失败原因分类：分类路径/套图/描述/价格/发货 | 每类给一个修复动作 |
| 6. 收尾 | 核对状态、导出日志、备份清单 | 交付物齐全 |

## 5. 验收单

### 5.1 验收样本

| 项 | 要求 |
|---|---|
| 样本数量 | 10 行（建议 8 行资料完整 + 2 行故意缺字段） |
| 平台 | 闲鱼 |
| 环境 | 干净 profile + 测试账号 |
| 时间 | 单批 ≤ 30 分钟（待验证） |

### 5.2 通过标准

| # | 检查项 | 通过标准 | 结果 |
|---|---|---|---|
| 1 | 批量执行 | 10 行全部被处理，无卡死 | ☐ |
| 2 | 成功数 | 资料完整的 8 行成功 ≥ 7 | ☐ |
| 3 | 失败可解释 | 每个失败行有明确原因 | ☐ |
| 4 | 不明可识别 | 无法确认的行标「不明」，不标失败 | ☐ |
| 5 | 不重复上架 | 重跑不会重复发布（除非人工置待上架） | ☐ |
| 6 | 中断可续跑 | 登录失效后重新登录，能从断点继续 | ☐ |
| 7 | 可追溯 | 日志/ledger 能查到每行处理记录 | ☐ |
| 8 | 无需改代码 | 全程只改 Excel，不改代码 | ☐ |

> 8 项全过 = 交付通过；1/4/5 任一不过 = 不通过。

## 6. 异常分类与处置

| 现象 | 可能原因 | 处置 | 谁处理 |
|---|---|---|---|
| precheck 拦截整批 | 套图缺失/列未填 | 补齐后重跑 | 运营 |
| 某行「上架失败」 | 分类路径、价格、发货、描述、套图 | 按第 14 列原因修复，置回待上架 | 运营 |
| 「中断·登录失效」 | 登录态过期/被踢 | 重新扫码，续跑 | 执行人 |
| 残留「上架中」 | 运行中崩溃 | 先 `reconcile.py` 对账，再决定 | 执行人 |
| 「上架情况不明」 | 已点发布但未跳转 | 到闲鱼后台核对，人工修正 | 运营 |
| 分类选项找不到 | 平台分类调整 | 更新 `xianyu_category` 的匹配规则 | 维护人 |
| 描述重复/叠加 | contenteditable 未清场 | 检查 Ctrl+A 清场逻辑 | 维护人 |

## 7. 责任边界

| 包含 | 不包含 |
|---|---|
| 按清单批量上架 | 选品、定价策略 |
| 状态回写与失败原因 | 客服、售后、发货履约 |
| 登录态复用与中断提示 | 代运营、店铺运营 |
| 运行手册与异常处置说明 | 平台规则变化导致的改版适配（另议） |
| 单平台（闲鱼） | 多平台铺货（淘宝/拼多多/抖店） |
| 单账号、顺序跑 | 多账号、并发、代理池 |
