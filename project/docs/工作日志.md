## E15 · 两阶段台账 + 对账

**事件**：P0 里最后一项。讨论对账时被追问「为什么无法判断已上架/待上架」，由此定下设计。

**问题**：
- 原台账只记**结果**，不记**意图**——崩溃后分不清「还没开始」和「点了发布但没回来」
- 纠正了最初的说法：不是"无法判断"，而是**"能证明没发，不能证明发了"**
- 判定依据不在本地（闲鱼无可查询接口），任何本地逻辑只能给意见

**成果**：
- **状态机**：`inflight（已 claim）→ confirmed / failed / unknown / released`
- `check()` **只认 confirmed** —— inflight / released 不算"发过"，否则一次崩溃就会把商品永久锁死
- `inflight(lease=30min)` 只看超租约的 claim，正在跑的不打扰
- `tools/reconcile.py`：把「上架中」列成核对清单（含描述、价格、首图、台账状态）→ 人工去闲鱼核对 → `--set 行=已发布/未发布` 回填 Excel + 台账
- **两条红线**：脚本永不自动判定结果；「上架中」永不被自动改回「待上架」（那是重发开关）
- 82 条测试全绿（新增 15 条，含「inflight 不能被当成已发布」这条关键回归）

**留给 O2b**：画布尚无 `publish_begin` 日志，所以「崩在哪一段」目前只能靠人看时间推断；加日志要等 S4 跑一次验证。

## E18 · 混合模式落地 + 首个真实上架（2026-11-09）

**事件**：把执行路径从「192 块画布」改为「影刀 main 编排 + 8 个步骤 CodeFlow（Python/DrissionFlow）」，
用户手动删除 process3/process4。第一次用新链路真实上架 P005。

**过程与问题**：

1. **影刀不把应用目录放进 `sys.path`**：步骤间 `import xianyu_common` 直接失败（`ModuleNotFoundError`）。
   修法：每个模块头部加垫片 `sys.path.insert(0, HERE)`（与项目一 `ui_action` 同款）。
2. **main 调发布步骤没传 `confirm_publish`**：发布步走 dry 不点击，随后的判定步看到「发布按钮还在」会补点一次——
   状态会记失败但商品实际已发。修法：main 的发布调用显式传 `confirm_publish=True`。
3. **分类品牌下拉异步**：固定等 0.8s 后扫描经常撞空列表；且点完用旧句柄复核必失败。
   修法：选项轮询（最多 5s）+ 点完后重新取表单字段复核，失败重试一次。
4. **成功锚失效**：发布成功后页面直接跳 `/item?id=…`，原「页面含咸鱼ID」锚在商品页不成立，误判「不明」。
   修法：第一锚改为 URL 含 `/item`，旧锚兜底。
5. **台账查重未接入 main（O4 回退）**：原 Python 编排会拦 confirmed 的 ID，现在画布编排没有这道闸，
   本次发布产生 P005 重复 listing（`id=1096805699542`），已由用户人工下架。

**成果**：
- 新链路真实跑通：precheck 5/0 → 登录 → 上传 → 描述 → 分类五字段 → 价格 → 发货 → 发布 → 跳商品页，约 30 秒
- 证据：`runtime/logs/run_20261109_192952/events.jsonl`（`PUBLISH|begin/click/verdict` 齐全）
- 节点测试 44 条全绿；画布 main 55 块转录与快照已更新；192 块转录归档到 `docs/archive/`
- `check_block_refs` 对已归档转录改为 SKIP；`transcribe_canvas` 移除 process3 映射
