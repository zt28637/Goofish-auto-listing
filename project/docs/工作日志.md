## E15 · 两阶段台账 + 对账

**事件**：P0 里最后一项。讨论对账时被追问「为什么无法判断已上架/待上架」，由此定下设计。

**问题**：
- 原台账只记**结果**，不记**意图**——崩溃后分不清「还没开始」和「点了发布但没回来」
- 纠正了最初的说法：不是"无法判断"，而是**"能证明没发，不能证明发了"**
- 判定依据不在本地（闲鱼无可查询接口），任何本地逻辑只能给意见

**成果**：
- **状态机**：`inflight（已 claim）→ confirmed / failed / unknown / released`
- `check()` **只认 confirmed** —— inflight / released 不算"发过"，否则一次崩溃就会把商品永久锁死
- `inflight(lease=30min)` 只看超租约的 claim，正在跑的不打扰
- `tools/reconcile.py`：把「上架中」列成核对清单（含描述、价格、首图、台账状态）→ 人工去闲鱼核对 → `--set 行=已发布/未发布` 回填 Excel + 台账
- **两条红线**：脚本永不自动判定结果；「上架中」永不被自动改回「待上架」（那是重发开关）
- 82 条测试全绿（新增 15 条，含「inflight 不能被当成已发布」这条关键回归）

**留给 O2b**：画布尚无 `publish_begin` 日志，所以「崩在哪一段」目前只能靠人看时间推断；加日志要等 S4 跑一次验证。
