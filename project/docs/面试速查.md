## 0. 三十秒电梯陈述

> 「我做了一个闲鱼批量上架的执行系统：影刀负责操作真实网页，我给整个流程建了预检、状态机、故障兜底和一致性校验。我主要的工作不是写指令，而是**定义什么叫成功、划定哪里不许自动化、设计崩溃后怎么恢复**，并且让 Agent 在这个边界内改流程。」

## 1. 必须能打开并指清的 5 个文件

### ① `project/tools/precheck.py` — 最容易讲、也最像"工程"的一段

| 要能说出 | 内容 |
|---|---|
| 核心函数 | `check_row(vals, seen_depths)`：**纯函数**，输入一行数据，返回 `(fails, warns)`，不读写文件、不开浏览器 |
| 为什么纯函数重要 | 可单测、可复现、不依赖环境 —— 这也是 29 条用例能秒跑的原因 |
| 两级判定 | `fail` = 一定跑不通（整批停）；`warn` = 可疑但能跑（只提示） |
| 自学习 | `_seen_depths()` 从「上架成功」的历史行里学每个品类几级，新行层数不一致 → `CAT_DEPTH` 警告 |
| 双环境入口 | `main()` 收到参数走影刀分支（返回 dict 不 exit），无参数走命令行分支 |

**会被问**：「为什么预检和执行业务要分开？」
**答**：预检是纯离线的，零风险、可单测；执行要登录、要发商品，不可逆。把能离线判的全放前面，越靠前的拦截越便宜。

### ② `project/tools/canvas_snapshot.py` — 讲「可回滚」

- `fetch_blocks()` 分页拉全量画布（含每个块的填写值）
- `diff_summary()` **按 `block_id` 追踪**，输出 `+新增 / -删除 / ~填写值变更`
- `--check` 只比对不落盘

**会被问**：「你说的可回滚，具体怎么做到？」
**答**：单文件快照 + git 历史 = 版本链。改动前存一份，`git diff` 看改了什么，`git checkout` 拿回旧版。之前回滚只能靠人记忆——今天真实发生过。

### ③ `project/tools/check_truth_source.py` — 讲「单一真相源」

四路比对：**画布实际块数 = 转录 `.md` 表头 = 快照 `block_count` = README/AGENTS 里的声明**。

**会被问**：「为什么要这个？」
**答**：因为人（改画布 GUI）和 Agent（走 MCP）都会改流程，真相源一定会分叉。第一次跑它就抓到我漏改的两处文档。

### ④ `project/modules/` — 步骤代码 + `主流程_main.md`（55 块编排）

**混合模式**：`main` 画布负责 Excel 循环/状态过滤/回写/收尾；每个步骤是独立 CodeFlow（Python + DP），
元素表归各自文件所有。不要背块号，用 grep：

```bash

grep -n "def choose_category" -A20 project/modules/4.选择分类/xianyu_category.py
grep -n "def judge" -A15 project/modules/8.判定回写/xianyu_verdict.py
grep -n "PUBLISH|" project/modules/7.发布/xianyu_publish.py
```

> 192 块旧画布的转录归档在 `project/docs/archive/`，只作审计，不对应可执行流程。

### ⑤ `project/docs/失败模式清单.md` — 体现工程成熟度

按 **触发条件 → 代价 → 检测 → 应对** 写，标 🔴🟡🟢⚪。

**会被问**：「这些坑你都踩过？」
**答**：不全是。⚪ 是"同类项目常见、我这没遇到，但我知道它什么时候会来"。**状态不是罪，未知才是。**

## 2. 三个核心设计（必须能脱稿讲）

### ① 状态机，而不是流水线

Excel N 列：`待上架 → 上架中 → 上架成功 / 上架失败 / 上架情况不明，待人工确认`

- 发布**前**写「上架中」并立即保存 → 崩溃后能知道卡在哪
- 判定**后**回写三态 → 已成功的行不会重发（入队只认「待上架」）
- 「情况不明」是给人留的出口 —— **不为了自动化而假装确定**

> 一句话：**幂等 + 可恢复 + 人工兜底状态。**

### ② 人机边界

登录失效 → 写「中断·登录失效」→ 退出循环，**不自动重登**（滑块/扫码属人类区）。

> 一句话：**能主动说「这里不该自动化」的人，通常也不会在生产环境乱来。**

### ③ 判定标准来自实测，不是推测

- 成功判据 = 页面出现「咸鱼ID」元素，**不信 toast**（toast 会说谎）
- 级联/动态元素先滚动到视口中上部
- 多选脏值先 `{BACKSPACE}` 清空再重勾

> 一句话：**Agent 能写「点击→等待→判断成功」，但它不知道 toast 可信度是零。**

## 3. 三个故障案例（讲故事用，数字都对得上）

### 案例 A：收尾必崩，但没人发现日志从来没生成过

- **现象**：每轮结束后报 `an integer is required (got type str)`
- **定位**：报错归属「主流程」，是它最后一块——导出日志
- **根因**：`当前时间` 是 datetime 对象，代码写成 `.replace(':','-')` → 实际调用 `datetime.replace(year=…)`，传字符串炸
- **处置**：改 `strftime('%Y-%m-%d_%H-%M-%S')`
- **旁证**：`runtime/logs/` 一直是空的 —— **一次都没导出成功过**，说明这个错存在很久了

> 讲这个案例的重点：**错误信息里的 `an integer is required` 和 `datetime.replace` 看起来毫无关系**，是顺着「哪一块能报这个错」倒推出来的。

### 案例 B：整批卡死 20 分钟的死循环

- **现象**：跑着不动，日志每 21–25 秒重复一次「目标值=全新」
- **根因**：分类路径段序错位（Excel 第 4 段写「全新」，但页面第 4 个框是「连接方式」）→ 选项匹配不到 → 级别不前进 → While 无限重试
- **处置**：两道守卫 —— ①级别未推进 ②等待超 10 次 → 判「上架失败」并跳过该行
- **认知**：**这类错误离线预检判不了**（只有页面知道每级候选值），所以不是"预检漏了"，而是"执行层必须能安全失败"

### 案例 C：陈旧句柄的竞态

- **现象**：`未找到指定ID的元素`，整轮 abort，**时好时坏**
- **根因**：点击下拉框后 React 重渲染，之前抓的元素句柄作废
- **处置**：点击后**重新抓一次**分类框（治根）+ 外层 `Try/Catch`（兜底）
- **认知**：竞态类 bug 的修复要**根因 + 兜底两层**，只有兜底会掩盖问题，只有根因会漏掉别的触发路径

## 4. 你必须知道的「Agent 会错在哪」

**这是最容易被追问、也最能加分的部分。** 当天 Agent 犯了 5 个错，全部靠人的现场观察纠正：

| # | 错误 | 怎么发现的 |
|---|---|---|
| 1 | 把出 bug 的表达式当成修法写进了失败清单 | 人读文档时发现逻辑反了 |
| 2 | 插入 `Catch` 时先于 `Try`，破坏作用域，整棵树校验失败 | 系统回滚 + 人看到报错 |
| 3 | 提出「成色词不该出现在非成色位置」的启发式 | 人指出：`发饰/DIY/全新/抓夹` 里 `全新` 就是分类节点 |
| 4 | 用旧克隆档案带调试端口打开发布页 | **触发平台风控，需扫脸+改密** |
| 5 | 把「零成功」先解释为状态过滤（这次是对的） | 人补充"连一次上传都没有"，才定位到循环体 |

> **一段可以背下来的话**：
> 「Agent 的产出是**高置信度的猜测**。它错的时候和它对的时候语气一样。所以我的工作是给它建可验证的边界——单测、快照 diff、一致性检查、失败码回写。**不是问它做得对不对，是让系统自己证明。**」

## 5. 高频追问速答

| 问题 | 答 |
|---|---|
| 为什么用影刀而不是 Selenium/Playwright？ | 业务方要可视化维护，画布改动能被非程序员接手；我只在"给 Agent 造能力"时才用代码 |
| 为什么快照不自动提交？ | 副作用要可控。默认只写文件，`--commit` 才提交，避免 Agent 悄悄改写历史 |
| 预检为什么不判断分类对不对？ | 离线判不了。试过用"成色词"推断，被真实数据证伪——`全新` 在闲鱼既是分类节点又是字段值 |
| 重复发布怎么防？ | 状态机（已成功不再入队）+ 台账查重（S3 待做）。今天真实发生过一次重复，是人工下架的 |
| 失败了怎么恢复？ | 三态 + 「上架中」残留对账（S3 待做）；当前是人工对账，已写进 AGENTS 约束 |
| 量有多大？ | 目前单批 5 件。设计上不依赖规模，瓶颈在串行发布和平台节流 |
| Agent 写的代码你怎么保证质量？ | 不保证，只验证：29 条单测 + 快照 diff + 一致性检查 + 真实数据零误伤回归 |
