## 1. 这个节点是干什么的

- **一句话**：把 Excel 第 7 列（`价格`）和第 8 列（`原价`）分别填进发布页的售价框、原价框。
- **没它会怎样**：价格为 0/空时发布按钮不可用或商品被低价误拍；原价错会误导买家并可能触发平台价格审核。
- **它不负责**：不计算价格、不做折扣、不校验「原价 ≥ 售价」（预检 `PRICE_ORDER` 兜底）。
- **边界**：只负责把两个数字填进去；填完不回读、不改值。

## 2. 总流程

```text
填写价格（画布 043 调用 {row: list(loop_excel)}）
  │
  ├─ pick 售价框 → scroll.to_see()（先滚到可视区）
  │   ├─ 找不到 → 失败
  │   └─ 点击 → 键入 Excel 索引 6（售价）
  │
  ├─ 点原价框 → 键入 Excel 索引 7（原价）
  │   └─ 找不到/键入失败 → 失败
  │
  └─ 返回 {"ok": true, "step": 5}
        └─ 异常 → {"ok": false, "step": 5, "error": "..."}
             └─ 画布 044–047：写「上架失败」→ 保存 → 继续下一行
```

## 3. 动作细节

```text
fill_price(page, row)
├─ ui_action.pick(价格输入框, timeout=20)
│   ├─ 候选 1：长 XPath
│   └─ 候选 2：css:input[placeholder='0.00']
│       └─ 全不中 → RuntimeError → ok=false
├─ .scroll.to_see()                     ← 价格区在视口下方
├─ click(价格输入框) → type(cell(row, 6), 0.05)   ← 售价
├─ click(原价输入框) → type(cell(row, 7), 0.05)   ← 原价
└─ 返回
```

| 参数 | 说明 | 默认值 |
|------|------|--------|
| 售价 | Excel 0 基索引 6（第 7 列） | 空则键入空串 |
| 原价 | Excel 0 基索引 7（第 8 列） | 空则键入空串 |
| 页面元素 | `价格输入框`：长 XPath → `css:input[placeholder='0.00']`；`原价输入框`：**只有一条 XPath** | — |

**判断标准**：

| 结论 | 判据 |
|------|------|
| 成功 | 两个框都点到且键入不抛错 |
| 失败 | 任一框找不到 / 点击抛错 / 键入抛错 |

> 不判断「值是否正确」：没有回读，无法发现「填反」或「小数点丢失」。

**失败怎么办**：

| 现象 | 判据 | 后果 |
|------|------|------|
| 售价框找不到 | 两条候选落空 | `ok=false`，写「上架失败」 |
| 原价框找不到 | 唯一 XPath 失效 | 同上 |
| 元素在视口外 | 点击抛错 | 同上（滚动只对售价框做了） |
| 原价为空 | 键入空串 | 不报错，依赖预检/人工口径 |

> **原价框只有一条 XPath 候选**，是最容易随改版失效的元素；若频繁失败，应补语义候选（如按相邻 label 定位）。

## 4. 对外契约

| 项 | 现状 |
|----|------|
| 返回值 | `{"ok": bool, "step": 5, "error": "..."}` |
| 售价列 | 0 基索引 6（第 7 列 `价格`） |
| 原价列 | 0 基索引 7（第 8 列 `原价`） |
| 滚动 | 售价框先 `scroll.to_see()` |
| 回读校验 | **未做**（E7/G6） |

> 价格填错是「能发出去但会亏钱」的错误，比失败更危险；回读校验属于后续硬化项。
