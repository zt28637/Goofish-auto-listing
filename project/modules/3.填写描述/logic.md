## 1. 这个节点是干什么的

- **一句话**：把 Excel 第 13 列（`描述`）的文本，**覆盖**写进发布页的 contenteditable 描述框。
- **没它会怎样**：
  - 描述为空 → 商品说明缺失，买家看不到关键信息。
  - 描述残留上一件草稿 → 串货，严重时描述与图片/价格对不上。
- **它不负责**：不生成文案、不查违禁词、不校验长度（预检 `DESC_LONG` 兜底）、不点发布。
- **边界**：只处理「描述框清场 + 写入」；描述框找不到就失败，不尝试别的输入方式。

---

## 2. 总流程

```text
填写描述（画布 031 调用 {row: list(loop_excel)}）
  │
  ├─ 点描述框（长 XPath → css:[contenteditable=true]，timeout=20）
  │   └─ 找不到 → 失败
  │
  ├─ Ctrl+A 清场（contenteditable 不会自动覆盖）
  │
  ├─ 键入 Excel 索引 12（描述），逐字 interval=0.05
  │
  ├─ 等 1s
  │
  └─ 返回 {"ok": true, "step": 3}
        └─ 异常 → {"ok": false, "step": 3, "error": "..."}
             └─ 画布 032–035：写「上架失败」→ 保存 → 继续下一行
```

## 3. 动作细节

```text
fill_description(page, row)
├─ ui_action.click(描述输入框, timeout=20)
│   ├─ 候选 1：css:[contenteditable=true]   （2026-11-18 起升为主候选）
│   └─ 候选 2：长 XPath                     （旧主候选，保留兜底）
│       └─ 全不中 → RuntimeError → ok=false
├─ sleep(1)（等聚焦/光标就位）
├─ actions.type((CONTROL, "a"))            ← 清场：全选
├─ actions.type(str(cell(row, 12)), 0.05)  ← 直接覆盖选区
└─ sleep(1)
```

| 参数 | 说明 | 默认值 |
|------|------|--------|
| 描述列 | 0 基索引 12（第 13 列） | 空字符串合法（会清空描述框） |
| 页面元素 | `描述输入框` | 长 XPath → `css:[contenteditable=true]` |
| 输入方式 | 逐字符键入 | `interval=0.05` |

**判断标准**：

| 结论 | 判据 |
|------|------|
| 成功 | 描述框点到且键入不抛错 |
| 失败 | 元素找不到 / 点击抛错 / 键入抛错 |

> 当前**不**判断「框内文本是否等于 Excel 值」。contenteditable 的 `Ctrl+A` 在个别输入法/焦点状态下可能只选中当前块，回读校验是后续可加的硬化点。

**失败怎么办**：

| 现象 | 判据 | 后果 |
|------|------|------|
| 描述框找不到 | 两条候选都落空 | `ok=false`，停本行，写「上架失败」 |
| 页面还停在上一件的 `/item` | 描述框不在 | 应由 N1 的 `open:true` 回跳避免 |
| 描述超长被截断 | 无法判断 | 预检 `DESC_LONG` 跑前拦 |

**有出处的结论**：

| 结论 | 证据 | 日期 |
|------|------|------|
| 描述框是 contenteditable，必须 `Ctrl+A` 清场 | 失败模式 E4；代码注释 | 2026-11-09 |

| 描述列 = 第 13 列（0 基 12） | 表头实测 + 代码 | 2026-11-17 |

**已知缺口**：

| 编号 | 问题 | 等级 | 现状 |
|------|------|------|------|
| E9 | 输入后不回读校验 | 🟡 | 未做 |
| E5 | 中文输入法 / IME 干扰 | 🟡 | 逐字键入；未强制英文输入法 |
| E8 | 表情 / 特殊字符 / 超长换行 | ⚪ | 预检只查长度与联系方式 |
